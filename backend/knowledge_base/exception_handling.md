# 配送异常处理说明

> 本文档描述系统的异常处理流程，实时异常以数据库事实及查询接口为准。

## 未分配需求

自动派车无法安排的需求会保留在方案的 unassigned_demands 中，并保留未分配原因。处理时应先根据实时业务 Tool 确认需求、出勤车辆和方案详情，再根据原因调整基础配置或草稿方案。

## 车辆出勤异常

车辆在方案生成后变为不出勤时，发布前全量校验应拒绝发布。调度员应重新生成方案或在 DRAFT 方案中执行通过后端校验的人工调整，不得直接修改已发布方案。

## 待计划需求

PENDING 需求可进入自动派车。DRAFT 方案是备选方案，同日重新生成新版本时可重新计算旧 DRAFT 中仍然有效的需求。PUBLISHED、DELIVERING、COMPLETED 和 CANCELLED 需求不应被当作新的待计划需求。

## 处理建议边界

知识库只提供处理原则，不包含当日实时车辆、需求或方案状态。涉及具体方案时必须调用业务 Tool。任何移动需求或取消方案的写操作都必须经过 Pending Action 人工确认。

每日异常页面显示未分配、出勤和车辆不可用、配送失败、缺回单、回单驳回及业务状态冲突。处理工单需引用真实业务记录、指定责任人并填写说明；版本冲突须刷新，不覆盖他人处理。

签收缺回单时补传；驳回回单保留原图，上传替代版本并重新审核。关闭这些工单前检查业务事实是否已纠正。配送失败工单结案只表示已记录后续处置，不会把失败签收改成成功。业务状态冲突未修正时不得关闭工单。
