# 物流派车业务规则

> 本文档描述当前系统的业务规则。具体配置以数据库中的企业资料为准。

## 候选车辆与线路

自动派车前需确认车辆在配送日期出勤且运行状态正常，门店、线路及车型均启用。门店可以属于多条线路，每趟选择的线路必须包含所有停靠门店，且属于车辆允许范围。地形通行许可根据车型和线路生效配置校验。

## 时段与载重

MORNING 需求只能分配到上午任务，AFTERNOON 需求只能分配到下午任务。每趟独立满足车型最低载重；最高载重取车型上限与车辆额定载重的较小值。没有填写车辆额定载重时使用车型上限，不能用全天合计代替单趟校验。

## 同车多趟

同一辆车在同一时段可以安排多个逻辑趟次，用 trip_no 区分。每趟都单独执行线路、地形、时段和载重校验。货物分类和温控能力匹配已停用，不属于当前校验条件。未开启需求拆分时，同一 DeliveryDemand 不能重复出现在多趟中。

车辆填写每日趟次上限时，上午与下午合计不得超过该上限。车型与载重由业务资料配置，不按固定车辆数量或固定载重推断。

## 方案发布

自动派车生成 DRAFT 方案。方案发布前必须基于当前出勤、线路、地形、车型参数和明细载重重新执行全量校验，司机可用性遵守现有排班和请假代班规则。货物分类和温控能力匹配已停用。任一趟校验失败时整个方案不得发布。

Agent 候选需独立确定性校验，人工采纳时检查签名、操作者和最新快照。人工调整走独立 Agent 草稿接口，核验内容版本并重新校验；发布需重新预览和人工确认，旧内容对应的发布凭据不能复用。模型不得直接保存或发布。
